#### 3.3. Проверка нормальности (строки 77-98)
**Тест Шапиро-Уилка:**
- H0 (нулевая гипотеза): данные распределены нормально
- Если p-value > 0.05 → принимаем H0 (нормальное распределение)
- Если p-value ≤ 0.05 → отклоняем H0 (не нормальное)

**Зачем это нужно:**
- Некоторые методы (например, линейный дискриминантный анализ) требуют нормального распределения
- Если распределение не нормальное, лучше использовать непараметрические методы (SVM, нейросети)

## БЛОК 5: Стандартизация переменных (строки 161-176)

### Зачем нужен:
- Привести все признаки к одному масштабу (среднее = 0, стандартное отклонение = 1)
- **Критически важно** для SVM и нейронных сетей!

### Что делает:
1. **До стандартизации:** признаки имеют разные масштабы
   - Например: sepal_length ~ 5-7 см, а sepal_width ~ 2-4 см
2. **После стандартизации:** все признаки имеют среднее = 0, std = 1
   - Формула: `(x - mean) / std`

### Почему это важно:
- SVM и нейросети чувствительны к масштабу данных
- Признак с большими значениями будет доминировать
- После стандартизации все признаки равноправны

## БЛОК 8: Построение моделей классификации (строки 246-316)

### Зачем нужен:
- Обучить две модели для сравнения
- Обосновать выбор параметров

### 8.1. Нейронная сеть MLP (строки 253-288)

**Архитектура:**
```
Вход: 4 признака
  ↓
Скрытый слой 1: 100 нейронов (ReLU)
  ↓
Скрытый слой 2: 50 нейронов (ReLU)
  ↓
Выход: 3 класса (softmax)
```

**Параметры и их смысл:**
- `hidden_layer_sizes=(100, 50)` - два скрытых слоя
  - **Почему:** достаточно для нелинейной классификации, но не переобучается
- `activation='relu'` - функция активации
  - **Почему:** ReLU лучше работает, чем sigmoid/tanh для глубоких сетей
- `solver='adam'` - оптимизатор
  - **Почему:** Adam адаптирует скорость обучения, работает быстрее SGD
- `alpha=0.001` - L2 регуляризация
  - **Почему:** предотвращает переобучение
- `learning_rate='adaptive'` - адаптивная скорость обучения
  - **Почему:** автоматически уменьшает скорость, если модель не улучшается
- `early_stopping=True` - остановка при отсутствии улучшений
  - **Почему:** предотвращает переобучение

### 8.2. Метод опорных векторов SVM (строки 290-316)

**Параметры:**
- `kernel='rbf'` - радиальная базисная функция
  - **Почему:** versicolor и virginica не линейно разделимы → нужна нелинейность
- `C=1.0` - параметр регуляризации
  - **Почему:** баланс между переобучением (большой C) и недообучением (малый C)
- `gamma='scale'` - автоматический выбор масштаба
  - **Почему:** gamma контролирует "радиус влияния" опорных векторов

### Зачем нужен:

### 9.1. Функция calculate_metrics (строки 325-349)

**Метрики:**
- **Accuracy** - доля правильных предсказаний
- **Precision (macro)** - точность, усредненная по классам
- **Recall (macro)** - полнота, усредненная по классам
- **F1 (macro)** - гармоническое среднее precision и recall
- **Precision/Recall/F1 (micro)** - микроусреднение (учитывает общее количество)
- **AUC** - площадь под ROC кривой (требует вероятности)

**Macro vs Micro:**
- **Macro:** считает метрику для каждого класса отдельно, потом усредняет
- **Micro:** считает общую метрику по всем классам вместе

## Общая логика программы

1. **Загрузка данных** → понимаем, с чем работаем
2. **Анализ данных** → проверяем нормальность, распределения
3. **Отбор признаков** → определяем важные признаки
4. **Стандартизация** → подготавливаем данные для моделей
5. **Визуализация** → видим расположение классов
6. **Разделение данных** → готовим train/test
7. **Обучение моделей** → создаем классификаторы
8. **Оценка качества** → считаем метрики, строим графики
9. **Анализ признаков** → определяем важность
10. **Эксперименты** → ищем лучшие параметры
11. **Упрощение модели** → удаляем малозначимые признаки
12. **Выводы** → резюмируем результаты

Каждый блок логически связан с предыдущим и готовит данные для следующего.
